# Known Issues

Актуальные незакрытые ограничения. Закрытые исторические проблемы сюда не возвращать.

1. **Stage 4 final Hosted Chat-originated acceptance ещё не выполнен.** Реальный Yandex polling-backend -> Windows acceptance уже успешно пройден 2026-08-09 (`local_ping`, `runtime_self_test`, controlled write/read, cleanup). Он доказывает один backend, но не делает Yandex каноническим transport. Остался запрос, инициированный Hosted Chat через доступный remote ingress; до него remote surface ограничен `local_ping` и `runtime_self_test`.
2. **Provider portability ещё не доказана реальным вторым backend path.** Windows polling client уже provider-neutral (`endpoint + secret_ref`), Rust `relay-server` имеет CI/integration acceptance, но нужен один реальный non-Yandex remote -> Windows round trip. Preferred target для MCP-capable callers — standard MCP Streamable HTTP through a mature direct/tunnel ingress; polling relay remains compatibility fallback.
3. **Стандартный MCP 2026-07-28 ingress ещё не переведён на официальный Rust SDK.** Текущий Rust relay содержит compatibility MCP JSON-RPC surface. Следующий отдельный change set должен использовать `rmcp` для стандартного MCP boundary, а не расширять самописную реализацию протокола.
4. **Первый versioned release/tag ещё не выпускался.** Package E2E доказал Windows binary + SBOM + MIT LICENSE + third-party notices -> ZIP -> SHA256SUMS, а release workflow содержит provenance attestation и immutable publish, но реальный `v0.2.0` tag-triggered publish ещё не проверен.
5. **Stage 18 adapters не реализованы.** Guarded one-shot confirmation primitive есть, но ни один внешний publishing/distribution executor пока не имеет права выполнять side effect.
6. **Python behavioral oracle всё ещё присутствует.** Он полезен для parity, но удваивает часть maintenance surface. Removal gate не пройден.
7. **Reference mastering benchmark технический, не музыкальный corpus.** Реальный Matchering engine и tonal/LUFS improvements проверяются на синтетическом PCM24 benchmark; subjective/professional quality на наборе реальных музыкальных материалов ещё не доказана.
8. **Artifact orphan cleanup намеренно консервативен.** Неизвестный `art_*` каталог без валидного recovery record сохраняется как unresolved, чтобы recovery не удалял потенциально полезные данные. Operator cleanup workflow пока отсутствует.
9. **Job/Confirmation stores используют линейный JSON lookup в отдельных сценариях.** Для текущего локального масштаба это приемлемо; retention/index нужны только после измеримого роста, а не как повод заранее вводить БД.
10. **Способы добровольной поддержки проекта ещё не опубликованы.** MIT License действует независимо от донатов; адреса кошельков/другие способы поддержки нужно добавить позже, не превращая их в условие лицензии.
11. **Stages 16/17 и конкретные Stage 18 adapters остаются conditional.** Browser/video/distribution surface не добавляется до конкретного пользовательского сценария и выбора лучшего подходящего edge-инструмента.
