# Known Issues

Актуальные незакрытые ограничения. Закрытые исторические проблемы сюда не возвращать.

1. **Hosted Chat ещё не переключён на принятый non-Yandex direct URL.** Публичная Tailscale Funnel цепочка уже реально прошла 2026-08-10: `https://id182019.tailc0abda.ts.net/gpt` -> Funnel -> `127.0.0.1:8787/gpt` -> `agent-platform` -> `local_ping`, с `status=success`, `pong=true`, `executed_locally=true`. Осталось изменить URL/credential существующего ChatGPT action/plugin и повторить `local_ping` именно из Hosted Chat. Это уже не network/reachability gap, а последний control-plane compatibility acceptance перед deprecation Yandex path.
2. **Native standard MCP `/mcp` path ещё не принят на реальном ChatGPT surface.** Historical Hosted Chat round trip закрывает Stage 4, direct `/gpt` compatibility ingress реализован, а public non-Yandex reachability доказана. Но standard MCP server через официальный `rmcp` ещё не добавлен; после его реализации нужен отдельный native acceptance.
3. **Стандартный MCP ingress ещё не переведён на официальный Rust SDK.** Текущий Rust relay содержит compatibility MCP JSON-RPC surface, а direct ingress намеренно сохраняет только текущий OpenAPI `/gpt` contract. Следующий protocol change set должен использовать current official `rmcp` для `/mcp`, а не расширять самописную реализацию стандарта.
4. **Polling relay/Yandex пока нельзя удалить.** Они больше не являются target architecture и `transport.relay_connect` optional. Public non-Yandex direct reachability уже доказана, но rollback/fallback сохраняется до двух acceptance gates: Hosted Chat-originated direct `/gpt` через Tailscale и native standard MCP `/mcp`.
5. **OpenAI Secure MCP Tunnel не является обязательным и не проверен на текущем аккаунте.** Это только optional private-reachability adapter; public HTTPS/reverse tunnel path не должен зависеть от него или от OpenAI Platform credentials.
6. **Первый versioned release/tag ещё не выпускался.** Package E2E доказал Windows binary + SBOM + MIT LICENSE + third-party notices -> ZIP -> SHA256SUMS, а release workflow содержит provenance attestation и immutable publish, но реальный `v0.2.0` tag-triggered publish ещё не проверен.
7. **Stage 18 adapters не реализованы.** Guarded one-shot confirmation primitive есть, но ни один внешний publishing/distribution executor пока не имеет права выполнять side effect.
8. **Python behavioral oracle всё ещё присутствует.** Он полезен для parity, но удваивает часть maintenance surface. Removal gate не пройден.
9. **Reference mastering benchmark технический, не музыкальный corpus.** Реальный Matchering engine и tonal/LUFS improvements проверяются на синтетическом PCM24 benchmark; subjective/professional quality на наборе реальных музыкальных материалов ещё не доказана.
10. **Artifact orphan cleanup намеренно консервативен.** Неизвестный `art_*` каталог без валидного recovery record сохраняется как unresolved, чтобы recovery не удалял потенциально полезные данные. Operator cleanup workflow пока отсутствует.
11. **Job/Confirmation stores используют линейный JSON lookup в отдельных сценариях.** Для текущего локального масштаба это приемлемо; retention/index нужны только после измеримого роста, а не как повод заранее вводить БД.
12. **Способы добровольной поддержки проекта ещё не опубликованы.** MIT License действует независимо от донатов; адреса кошельков/другие способы поддержки нужно добавить позже, не превращая их в условие лицензии.
13. **Stages 16/17 и конкретные Stage 18 adapters остаются conditional.** Browser/video/distribution surface не добавляется до конкретного пользовательского сценария и выбора лучшего подходящего edge-инструмента.
