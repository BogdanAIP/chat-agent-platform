# Known Issues

Актуальные незакрытые ограничения. Закрытые исторические проблемы сюда не возвращать.

1. **Native standard MCP `/mcp` path ещё не принят на реальном ChatGPT surface.** Hosted Chat -> plugin -> Yandex -> Windows -> ChatGPT уже реально прошёл 2026-08-06, поэтому Stage 4 закрыт. Но историческое подключение не сохранило достаточно metadata, чтобы утверждать, что оно использовало сегодняшний стандартный MCP Streamable HTTP. Нужен отдельный direct acceptance после перехода локального server boundary на `rmcp`.
2. **Provider portability ещё не доказана реальным вторым backend path.** Windows polling client уже provider-neutral (`endpoint + secret_ref`), Rust `relay-server` имеет CI/integration acceptance, но перед deprecation Yandex нужен один реальный non-Yandex remote -> Windows round trip. Это migration/deprecation gate, а не незакрытый Stage 4 gate.
3. **Стандартный MCP ingress ещё не переведён на официальный Rust SDK.** Текущий Rust relay содержит compatibility MCP JSON-RPC surface. Следующий отдельный change set должен использовать current official `rmcp` для standard MCP boundary, а не расширять самописную реализацию протокола.
4. **OpenAI Secure MCP Tunnel не является обязательным и не проверен на текущем аккаунте.** Current OpenAI plugin docs также допускают обычный public HTTPS Streamable HTTP `/mcp`; tunnel нужен только как optional private-reachability adapter и требует отдельного OpenAI Platform tunnel/runtime access. Не связывать core или release с наличием tunnel.
5. **Первый versioned release/tag ещё не выпускался.** Package E2E доказал Windows binary + SBOM + MIT LICENSE + third-party notices -> ZIP -> SHA256SUMS, а release workflow содержит provenance attestation и immutable publish, но реальный `v0.2.0` tag-triggered publish ещё не проверен.
6. **Stage 18 adapters не реализованы.** Guarded one-shot confirmation primitive есть, но ни один внешний publishing/distribution executor пока не имеет права выполнять side effect.
7. **Python behavioral oracle всё ещё присутствует.** Он полезен для parity, но удваивает часть maintenance surface. Removal gate не пройден.
8. **Reference mastering benchmark технический, не музыкальный corpus.** Реальный Matchering engine и tonal/LUFS improvements проверяются на синтетическом PCM24 benchmark; subjective/professional quality на наборе реальных музыкальных материалов ещё не доказана.
9. **Artifact orphan cleanup намеренно консервативен.** Неизвестный `art_*` каталог без валидного recovery record сохраняется как unresolved, чтобы recovery не удалял потенциально полезные данные. Operator cleanup workflow пока отсутствует.
10. **Job/Confirmation stores используют линейный JSON lookup в отдельных сценариях.** Для текущего локального масштаба это приемлемо; retention/index нужны только после измеримого роста, а не как повод заранее вводить БД.
11. **Способы добровольной поддержки проекта ещё не опубликованы.** MIT License действует независимо от донатов; адреса кошельков/другие способы поддержки нужно добавить позже, не превращая их в условие лицензии.
12. **Stages 16/17 и конкретные Stage 18 adapters остаются conditional.** Browser/video/distribution surface не добавляется до конкретного пользовательского сценария и выбора лучшего подходящего edge-инструмента.
