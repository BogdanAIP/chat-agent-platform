# Vision

Let ordinary ChatGPT use the user's own Windows computer as a modular professional capability surface without forcing a second AI planner, a custom cloud backend or a monolithic local agent.

The product should stay ChatGPT-first:

```text
ordinary ChatGPT
  = reasoning / planning / adaptation

local companion
  = scoped execution
  + bounded perception
  + non-agentic procedural memory
  + lifecycle / verification
```

The bridge should remain boring and replaceable where possible: official Secure MCP Tunnel, a small truthful Chat-facing contract, replaceable focused backends and task-driven activation.

Capability growth should not mean plugin/tool explosion or permanent process growth. Concrete local programs are selected from actual user tasks and evidence rather than precommitted as a fixed roadmap list.

## User-teachable direction

The long-term product is not only “ChatGPT can access this computer.” It should become possible to show or successfully perform a procedure, compile that experience into a versioned coordinate-free skill, and let ChatGPT reuse it later as guidance while adapting to the current state.

```text
successful work
  -> structured trajectory
  -> verified procedural skill
  -> future ChatGPT task
  -> current state + remembered guidance
  -> safe capability execution
```

Remembered procedure never becomes a second planner or blind macro. Current observed state remains authoritative and completion is verified.

## Windows desktop direction

Browser/file foundations are not the final local capability boundary. A scoped Windows desktop surface is an explicit planned layer. It should prefer native/deterministic UI information, use screen/vision only where needed, and keep keyboard/mouse actuation reviewed and fail closed.

Only after this desktop surface exists should the project decide whether the current five public tool names are sufficient or whether a few new truthful semantic capabilities are required.

## Product-ready direction

A stable product requires not only capability demonstrations but normal installation, repair/update/rollback/restart recovery, clean-user E2E and clear privacy/security boundaries for procedural memory and desktop observation.
